- (decision) Product name: OperatorDesk. Fast path chosen by user -- draft with [ASSUMPTION] tags, no creative-tool detour.
- (decision) Form factor: single-surface responsive web, desktop-primary (operators work at a desk on calls). Stack: React + Vite + TypeScript + Tailwind + shadcn/ui (SPA against the existing FastAPI backend -- no Next/SSR needed, no server-rendering requirement).
- (decision) One app, two role-gated areas (operator, admin) behind shared login + JWT. Sidebar/nav differs by role. [ASSUMPTION] light+dark mode both supported (low-cost with shadcn, matches professional-SaaS expectation).
- (decision) Scope boundary: this new frontend owns the operator review/fill workflow (queue, fill form, permission requests, operator stats/profile) and admin operator-management (create operators, approve/deny permission requests, stats dashboard). It does NOT rebuild raw company scrape CRUD or scrape-trigger controls -- those stay in the existing SQLAdmin panel, reachable separately. Avoids duplicating already-working functionality.
- (decision) Notifications: polling-based (e.g. every 15s), not WebSockets, for this first version -- [ASSUMPTION] simplest thing that delivers 'darhol' (prompt) feel without new realtime infra; upgradable later.
- (decision) Per-field review model: each company has two independent review fields (website, lms), each with its own available:boolean, comment:text, filled_by, locked state, and permission-request lifecycle -- filling one does not lock the other.
- (event) Key-screen mock rendered and published as artifact: login, operator queue, company review (mixed editable/locked field states), admin dashboard. Copied to mockups/key-screens.html.
- (event) User confirmed the design (colors, layout, flows) after fixing broken mock interactivity (CSP blocked inline onclick). Proceeding to architecture update + implementation.
